# 🏠 林北小財庫 (Family Budget App)

這是一套專為現代家庭量身打造的跨平台、高客製化、即時同步的共同記帳系統。

---

## 壹、 開發記帳 App 背景與目標

**「為什麼我們要自己開發記帳 App？」**

市面上的記帳軟體多如牛毛，但我們面臨了一個無法妥協的痛點：**手機系統的跨平台障礙**。家人之間使用的手機作業系統不同（Android 與 iOS 並存），導致市面上絕大多數的記帳 App 無法實現完美的雙平台無縫共享與即時同步。

此外，每個家庭的消費習慣、商家分類、付款方式（如特定的行動支付綁定特定的信用卡）都不盡相同，現成軟體僵化的設定根本無法滿足我們對「客製化」與「自動化防呆」的高度需求。為了解決這個問題，我決定親自研發這套「林北小財庫」。

**核心目標**：
1. **打破系統藩籬**：採用 React + Firebase 雲端架構，只要有瀏覽器（Safari 或 Chrome），不論蘋果或安卓手機都能完美運行並即時同步。
2. **極致的客製化與自動化**：從主頁顏色、消費分類、自訂商家，到「選擇某項目自動帶入商家與特定信用卡」的連動規則，全都能由家庭成員自行定義。
3. **直覺的家庭共享**：建立「房間」概念，家庭成員輸入通關密碼即可加入，並具備資料隔離（僅限本人修改）的安全機制。

## 貳、 記帳 App 操作使用手冊及核心邏輯概念

本系統設計以「低阻力輸入、高動態回饋」為核心，以下為各模組的詳細操作指引與底層自動化運作邏輯：

### 1. 基礎記帳步驟指南
當使用者點擊首頁底部橘色的「＋」號時，系統會開啟全螢幕的記帳工作流表單，頂部提供「支出」、「收入」、「轉帳」三個分頁標籤：

* **⚠️ 共同核心步驟（金額運算）**：進入表單後，點擊巨大的「金額區塊」會喚醒「安全沙盒計算機」。可直接進行 `+ - × ÷` 複合式運算（例如：買菜 `120 + 85 * 2`），點擊「確認金額」系統會自動取整數帶回表單，解決切換手機計算機的破碎體驗。
* **🌸 支出（Expense）記帳流程**：
    1. **選定日期與頻率**：預設為今天。若補登過去帳目，系統會亮起紅色閃爍警示標籤。
    2. **分類項目雙層選擇**：於「主分類」選定大項（如 `🍔 飲食`），右側會動態渲染該分類專屬的子項目（如 `早餐`）供精準勾選。
    3. **觸發自動帶入規則**：選定項目後，系統會在背景查詢 `autoFillRules`。例如選定 `早餐`，下方的「商家」會秒級自動帶入 `早餐店`。
    4. **觸發付款方式規則**：當「商家」帶入後，立即觸發第二層監聽（`methodRules`），自動將付款方式切換為 `信用卡` 並帶入子帳戶 `點點卡`。
    5. **確定對象與存檔**：勾選為誰花錢（可複選），可選填備註或拍照，最後點擊「儲存紀錄」秒級寫入雲端。
* **💰 收入（Income）記帳流程**：選擇「收入分類」，勾選歸屬對象，於「存入帳戶」選擇資金去向（如：`銀行` ➜ `元大銀行`），儲存後自動為該帳戶增加資產。
* **🔄 轉帳（Transfer）記帳流程**：用於帳戶資金移動（如繳卡費）。選擇「轉帳分類」，依序配置 **「📤 轉出帳戶」** 與 **「📥 轉入帳戶」**，此流向不計入家庭損益盈虧。

### 2. 財務總覽與統計報表查閱
* **📊 導覽至帳戶總覽**：點擊首頁「帳戶」按鈕進入。頂部看板即時加總「淨資產」、「總資產」與「總負債」。
    * **查看歷史明細抽屜**：點擊任一實體帳戶卡片，底部拉出歷史明細。完美應用「真實存摺滾動算法」，每一筆記帳右側皆會顯示歷經該筆消費後「當下的合計金額」，方便對帳。
* **📈 導覽至統計分析**：點擊首頁「統計」按鈕進入。
    * **進階多重條件篩選**：點擊「分析選單」啟動多維度複選，可同時勾選分類、項目、商家與付款方式。系統會將條件結合成複合式標籤（如：`飲食 - 飲料 - 50嵐`），渲染出高動態 SVG 圓餅圖。

### 3. 後台設定與規則配置指引
點擊首頁右上角「齒輪」圖示進入設定中心，此處主控整個房間的 DNA 結構：
* **分類與自訂清單維護**：透過 `SettingBlock` 對主分類、商家、信用卡清單進行增刪與拖曳排序。
* **自動化規則（AI 連動）配置**：
    * 建立「當項目為 `加油` ➜ 自動帶入商家 `加油站`」以及「當商家為 `加油站` ➜ 自動帶入 `信用卡(玉山)`」的規則鏈。
    * 利用 `↑ / ↓` 按鈕調整規則排序，排序愈上方擁有愈高的自動帶入優先權。
* **跨房間自動傳送配置**：在「其他」頁籤中可開啟「支出自動跨房間提示」。並可配置白名單，勾選「排除提示的花費對象」，讓個人私有花費不會觸發跨房彈窗。

### 4. 系統核心防呆與貼心設計矩陣
* **藥丸標籤智慧互斥邏輯**：選擇花費對象時，點擊 `全家` 會自動清空個人標籤；點擊個人則自動退選 `全家`，阻斷矛盾資料產生。
* **子項目與規則溯及既往**：在後台修改常見商家或信用卡名稱時，系統會啟動後台批量異動，自動將過去所有歷史紀錄中的舊名稱同步更新，確保報表不破裂。

### 📌 第貳點總結：
1. **房間與成員管理**：基於動態代碼與 PIN 碼的隔離環境，具備多房快速切換與本人資料鎖定修改權限。
2. **智慧防呆記帳表單**：內建安全運算沙盒、前端畫布縮圖優化，與「項目 ➜ 商家 ➜ 付款帳戶」的雙層連動自動帶入引擎。
3. **完美存摺式帳戶總覽（核心會計邏輯）**：背景採用「消費日期」由舊到新正向流動計算結餘，前台採用最新到最舊降冪渲染，契合真實存摺閱讀習慣。

## 參、 專案架構說明書

本專案採用標準的現代前端模組化架構（Component-Based Architecture），將大腦狀態、核心視圖、共用組件與底層工具嚴格分離。

```text
family-budget/
├── public/                     # 靜態資源資料夾
├── src/                        # 核心原始碼
│   ├── components/             # 共用設計系統組件庫
│   │   └── SharedUI.jsx        # 主控全應用高重複利用之 UI 元件與核心流水卡片
│   ├── firebase/               # 雲端配置與資料庫快取初始化
│   │   └── firebaseConfig.js   # 主控雲端連線、匿名認證與多頁籤持久化離線快取
│   ├── utils/                  # 全域狀態 Context 與純邏輯工具箱
│   │   └── helpers.js          # 主控台制日期、相容性 Emoji、沙盒運算與週期排程產生
│   ├── views/                  # 獨立高階視圖模組 (頁面級組件)
│   │   ├── LoginView.jsx       # 主控身分代碼驗證、防抖成員查詢與多房快速切換
│   │   ├── CreateRoomView.jsx  # 主控全新房間初始化與台版在地化模板寫入
│   │   ├── RoomView.jsx        # 主控 Dashboard 總覽、雙重條件過濾與滑動手勢切換
│   │   ├── RecordFormView.jsx  # 主控記帳表單狀態、內建計算機與圖片前端壓縮
│   │   ├── AccountsView.jsx    # 主控帳戶總覽：正向時間軸資產加減與動態累計結餘計算
│   │   ├── AnalysisView.jsx    # 主控多維度交集過濾與 SVG 圖表動報表解析
│   │   └── SettingsView.jsx    # 主控後台設定 CRUD、排序位移與歷史資料批量異動

└── tailwind.config.js          # 樣式原子化設定配置

### 📌 第參點總結：
1. **系統大腦與路由 (`src/App.jsx`)**：最高狀態調度中心，控管全域 Context、防抖動態身分加載，與攔截 Popstate 本機安全跳出網。
2. **資料庫與離線快取 (`src/firebase/firebaseConfig.js`)**：啟用 IndexedDB 持久化快取與多頁籤共用機制，主控斷網環境下 100% 正常記帳與多網頁即時背景同步。
3. **共用元件與 UI 骨幹 (`src/components/SharedUI.jsx`)**：封裝動態拉線 SVG 圓餅圖、聯動 MethodSelector，與完全展開自然水流換行的核心明細卡片 RecordItem。
4. **工具函式庫 (`src/utils/helpers.js`)**：專職無狀態代數運算，主控台制斜線格式化、Emoji 相容性降級演算法、沙盒計算引擎，與多維度大小月週期排程產生。

## 肆、 研發歷程與常見錯誤檢討 (Developer Insights)

在經歷多次架構更迭後，我們將曾遭遇過的隱蔽 Bug 完整記錄，作為後續研發與重構的最高防禦手冊：

### 🚨 錯誤點一：週期性排程的「雙胞胎幽靈紀錄」
* **錯誤現象**：建立新的週期性支出，或將其「跨房間傳送」時，存檔瞬間會在起始當天產生兩筆重複明細。
* **發生原因**：程式寫入第一筆主紀錄後，調用 `generateFutureDates` 產生未來排程並迴圈寫入。但該函數回傳的日期陣列預設包含起始當天，導致同一天被寫入兩次。
* **解決與防範**：凡是從日期產生器拿到的陣列，進入寫入迴圈前，必須強制掛上過濾器：`.filter(d => d > record.date)`，精準剃除起始當天。

### 🚨 錯誤點二：Vercel 生產環境編譯崩潰 (Syntax error)
* **錯誤現象**：本機測試正常，但推送到 GitHub 觸發 Vercel 部署時拋出 `Failed to compile`。
* **發生原因**：單行 Tailwind CSS 類別字串過長（300+ 字元）導致 Babel 解析超載；或是深層巢狀屬性中發生了輕微括號誤植（如 `)` 錯打成 `]`）。
* **解決與防範**：過長模板字串需換行拆解；嚴格落實 Commit 前的括號對稱檢查，第一時間查閱 Vercel Log 定位錯字。

### 🚨 錯誤點三：帳戶明細「顯示排序」與「結餘計算」的逆向衝突
* **錯誤現象**：補登過去帳目（如在 6/18 補記 3/1 的消費）時，該帳戶的結餘合計數字會全數算反，與實際金額脫鉤。
* **發生原因**：直接對為了前端閱讀而調整為「降冪（新到舊）」的陣列執行結餘累加，導致系統拿「今天」餘額扣「昨天」消費，違反時間軸正向推移。
* **解決與防範**：實施「計算與渲染徹底分離」。計算结餘時，嚴格依「消費日期(date)」由舊到新（升冪）排列並順向累加；算完綁定後，再執行由新到舊（降冪）排序輸出給 UI 渲染。

### 🚨 錯誤點四：信用卡負債分錄之正負號會計錯誤
* **錯誤現象**：記一筆信用卡消費，負債小計反而減少；轉帳還卡費時，負債反而飆高。
* **發生原因**：信用卡屬於「負債」，增減邏輯與現金相反（刷卡應是負債增加）。原代碼一律套用資產扣除公式導致會計分錄倒置。
* **解決與防範**：在 `balances` 計算矩陣中加入 `key.startsWith('cc_')` 判斷。若是信用卡帳戶，支出金額轉為 `+amt`，收入/轉入轉為 `-amt`。

### 🚨 錯誤點五：選單外部點擊監聽器造成的記憶體流失 (Memory Leak)
* **錯誤現象**：App 開啟一段時間後，每次開關選單或切換頁面會愈來愈卡頓，甚至瀏覽器崩潰。
* **發生原因**：`CustomDropdown` 元件在 `useEffect` 註冊了 `mousedown` 事件監聽器。但組件銷毀（Unmount）時，沒有移除該監聽器，導致每次開關選單全域就會多出無效監聽器吞噬記憶體。
* **解決與防範**：落實 React 資源回收。在註冊全域監聽的 `useEffect` 中，必須在 `return` 閉包中調用 `removeEventListener` 進行解鎖銷毀。

### 🚨 錯誤點六：非預期輸入字元造成計算機 `eval` 死鎖
* **錯誤現象**：計算機輸入連續運算子（如 `5++`）或未閉合括號時，畫面直接卡死。
* **發生原因**：底層解析使用了 `new Function`。語法不合法時，引擎拋出 `SyntaxError` 未被攔截，導致 React 渲染線程當機。
* **解決與防範**：在 `evaluateCalc` 中，全面使用 `try...catch` 沙盒塊包裹運算核心，並透過正規表達式預先清洗。捕獲錯誤立即中止並優雅回傳原字串。

### 🚨 錯誤點七：行動裝置獨立分頁重整 (Auto-Refresh) 造成的狀態丟失
* **錯誤現象**：填寫長表單中途切換去回訊息，切換回 App 時畫面自動重新整理，內容消失。
* **發生原因**：行動裝置為了節省資源，退到背景時隨時會回收 React 記憶體狀態。
* **解決與防範**：針對大型表單逐步引入「本機快取隔離機制」，狀態變更時同步寫入 `localStorage`，直到點擊「儲存」後才清空快取。

## 伍、 針對此 App 總結與未來建議

「林北小財庫」的誕生，成功解決了不同手機系統間難以共享財務數據的痛點，並透過高度的防呆連動設定，將家庭記帳的阻力降到了最低。系統底層對於非同步寫入、離線快取與時序邏輯的處理已趨於成熟穩固。

**🚀 未來發展與擴充建議：**

1. **PWA (Progressive Web App) 升級**：目前為網頁版應用，建議未來可在專案中加入 `manifest.json` 與 `Service Worker`，讓 iOS 與 Android 都能將其「加入主畫面」，獲得如同原生 App 般全螢幕的順暢體驗。
2. **年度預算系統 (Budgeting)**：利用現有的分類設定，為每個主分類擴充「每月/每年預算上限」欄位，並於統計分析頁面加入預算達成率的視覺化進度條。
3. **收據發票 OCR 自動辨識**：目前已實作前端相機圖片壓縮機制。未來可考慮串接 `Google Cloud Vision API`，讓系統自動掃描照片中的總金額與商家名稱，實現「拍照即記帳」的極致自動化。
